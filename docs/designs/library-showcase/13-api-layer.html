关注点 13 · C 业务基础设施 · ADR-0016

接口层与契约

挂在 Next Route Handler 里的轻量 API 框架，能从 zod schema 生成 OpenAPI。

我们需要什么

  • /api/v1 统一 REST，Web、APK 壳、未来 Kotlin 共用
  • 输出 OpenAPI 契约给 Kotlin 生成客户端
  • 中间件：鉴权、限流、幂等键、统一错误体 { code, detail }
  • 浏览器端有类型的客户端

候选

Hono 4 + @hono/zod-openapi

推荐hono

npm 描述："Web framework built on Web Standards"

  • hono 0 个依赖
  • @hono/zod-openapi：peer zod ^4、hono ≥ 4.10，从路由定义生成 OpenAPI 文档
  • App Router 用法：app/api/[[...route]]/route.ts（Hono 官方 Next.js 指南）
最近发布4.13.14（2026-10-25；12 个月内 67 次）
维护npm 维护者账号 1 个；GitHub ★32,760，最近提交 2026-10-30单个 npm 账号发布（bus factor）
体积服务端运行，不进客户端包（npm 解包 1.2 MB）；直接依赖 0 个，传递依赖 0 个
安装脚本包本身与传递依赖都没有 preinstall / install / postinstall
许可证MIT；依赖树无 copyleft
兼容性无相关 peer 依赖
类型包内自带类型声明
  • 官方示例用 @hono/vercel 的 handle()；是否可以直接导出 app.fetch、免装这个包，实施时先验证
import { createRoute, OpenAPIHono } from '@hono/zod-openapi'

const route = createRoute({
  method: 'get',
  path: '/users/{id}',
  request: { params: ParamsSchema },
  responses: { 200: { content: { 'application/json': { schema: UserSchema } }, description: '…' } },
})

const app = new OpenAPIHono()
app.openapi(route, (c) => c.json({ id: c.req.valid('param').id, name: '…', age: 20 }))

示例来源：https://hono.dev/examples/zod-openapi（为节省篇幅有删减）

原生 Route Handler + zod

备选

0 依赖

  • 不加框架

适合我们吗：OpenAPI、中间件链、类型化客户端都要自己写。

决定

所有者：Hono + @hono/zod-openapi，版本 hono 4.13.14、@hono/zod-openapi 1.6.3

封装层入口：src/app/api/v1/[[...route]]/route.ts 挂载；路由按领域写在 src/server/api/<领域>.ts；错误码登记在 src/server/api/errors.ts

  • handler 只做四件事：解析入参 → requireUser() → 调 service → 映射结果
  • OpenAPI 导出到 docs/specs/api/openapi.json 并提交，CI 检查与代码一致

放弃了什么：

  • oRPC：v2 大版本过渡中
  • 原生 Route Handler：契约和中间件要全部手写

已知代价：多两个服务端依赖（不进客户端包）。

何时重审：

  • oRPC v2 稳定且需要 RPC 风格时
