关注点 17 · C 业务基础设施 · ADR-0020

定时任务

这些"定时"大多可以改成"按周期懒计算"，不需要任务队列。

我们需要什么

  • 每周一 00:00 重置 AI 额度
  • 每天 00:00 重置全站花费上限
  • 额度异常时给管理员发邮件
  • 数据库每日备份（已由系统 cron 完成）

候选

按周期键懒计算 + 系统 cron

推荐

0 依赖

  • 额度行带 period_key（例如 2026-W44，按北京时间）；新周期第一次读写时在同一事务里重置
  • 全站日上限同理，用日期键
  • 告警在越过阈值的那次请求里发送，按"每天每种告警一次"去重

适合我们吗：服务器重启或停机也不会漏执行。

决定

所有者：不引入库：周期键懒计算 + 系统 cron

封装层入口：src/server/quota/（period.ts 计算周期键，依赖 src/lib/time/）

  • 周期计算只用 src/lib/time/ 的函数，并有单元测试覆盖周一、跨年、时区

放弃了什么：

  • pg-boss：MVP 没有需要队列的任务
  • 进程内定时器：停机会漏

已知代价：读写额度时多一个判断。

何时重审：

  • 需要提醒、周报等真正的定时任务时
