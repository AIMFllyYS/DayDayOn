关注点 3 · A 基础组件库 · ADR-0006

提示消息

跟随交互原语的所有者，避免出现第二套弹层、焦点和动画体系。

我们需要什么

  • 打卡成功、保存失败
  • 删除待办后"撤销"
  • AI 识别"处理中 → 完成 / 失败"
  • 在非 React 代码里也能调用（例如请求封装里统一提示错误）

候选

Base UI Toast

推荐@base-ui/react

npm 描述："Base UI is a library of headless ('unstyled') React components and low-level hooks. You gain complete control over your app's CSS and accessibility features."

  • 全局 toastManager：在 React 树之外也能 add / close / update / promise
  • promise 三态（loading / success / error）、actionProps 撤销按钮、按 id 更新
  • 滑动关闭、数量上限、F6 跳到提示区域
最近发布1.9.0（2026-10-09；12 个月内 13 次）
维护npm 维护者账号 8 个；GitHub ★11,270，最近提交 2026-10-31
体积实测 25.7 KB（min+gzip）；直接依赖 5 个，传递依赖 8 个
安装脚本包本身与传递依赖都没有 preinstall / install / postinstall
许可证MIT；依赖树无 copyleft
兼容性peer：react ^17 || ^18 || ^19；react-dom ^17 || ^18 || ^19
类型包内自带类型声明
补充单独打包的体积；和 Drawer、Dialog 一起打包时大部分代码共享

适合我们吗：覆盖全部需求，和关注点 1 是同一个依赖，不新增包。

决定

所有者：Base UI Toast，版本 跟随 @base-ui/react 1.9.0

封装层入口：src/components/ui/toast.tsx（导出 Toaster 和全局 toast 管理器）

  • 全站只有一个 Toast.Provider，放在根布局
  • 错误提示的文案从统一的错误码映射表取（见接口层规范）

放弃了什么：

  • Sonner：多一个依赖和一套样式体系
  • react-hot-toast：同上，能力更弱

已知代价：堆叠动画要自己用 CSS 变量写。

何时重审：

  • Base UI Toast 出现无法绕过的问题时
