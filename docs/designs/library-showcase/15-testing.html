关注点 15 · C 业务基础设施 · ADR-0018

测试

一个 TypeScript 原生的测试运行器；组件测试暂不做。

我们需要什么

  • 纯函数单元测试：额度预占与结算、热量计算、打卡日归属、连续打卡、邮箱规范化
  • service 集成测试连本地 PostgreSQL
  • CI 里不调用真实 DeepSeek
  • 界面验收用 ego-browser（不在测试框架里）

候选

Vitest 5

推荐vitest

npm 描述："Next generation testing framework powered by Vite"

  • 原生 TS / ESM
  • peer 依赖 vite ^6 / ^7 / ^8（需要一起装 vite）
最近发布5.0.5（2026-10-15；12 个月内 53 次）
维护npm 维护者账号 5 个；GitHub ★17,314，最近提交 2026-10-30
体积服务端运行，不进客户端包（npm 解包 2.7 MB）；直接依赖 13 个，传递依赖 22 个
安装脚本包本身与传递依赖都没有 preinstall / install / postinstall
许可证MIT；依赖树无 copyleft
兼容性peer：vite ^6.4.0 || ^7.0.0 || ^8.0.0
类型包内自带类型声明

适合我们吗：生态主流，配置少。

node:test

备选

0 依赖

  • Node 内置

适合我们吗：路径别名、模拟、覆盖率都要自己处理。

决定

所有者：Vitest，版本 5.0.5（+ vite）

封装层入口：vitest.config.ts；测试文件和被测文件放在一起（*.test.ts）

  • AI 相关测试用 AI SDK 的 mock 模型
  • pnpm test 加入 CI 的 verify job

放弃了什么：

  • node:test：工具链要自己拼

已知代价：多两个开发依赖。

何时重审：

  • 需要组件测试时（评估 Testing Library + happy-dom）
