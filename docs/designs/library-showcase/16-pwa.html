关注点 16 · C 业务基础设施 · ADR-0019

PWA 与 Service Worker

MVP 只要可安装 + 离线兜底，原生能力足够。

我们需要什么

  • 可以安装到桌面（manifest、图标）
  • 离线时显示兜底页
  • 离线草稿放到 v0.2（ADR-0003）

候选

app/manifest.ts + 手写 public/sw.js

推荐

0 依赖（约 50 行）

  • Next 官方 PWA 指南即采用 manifest.ts + 手写 Service Worker
  • 导航请求网络优先，失败时返回预缓存的离线页

适合我们吗：和 standalone 部署没有耦合。

Serwist（Turbopack 方案）

备选@serwist/turbopack

npm 描述："A module that integrates Serwist into your Next.js / Turbopack application."

  • 预缓存清单、运行时缓存策略、离线兜底
最近发布9.5.13（2026-10-04；12 个月内 21 次）
维护npm 维护者账号 1 个；GitHub 未核实单个 npm 账号发布（bus factor）
体积服务端运行，不进客户端包（npm 解包 0.1 MB）；直接依赖 9 个，传递依赖 未扫描 个
安装脚本未扫描
许可证MIT；依赖树未扫描
兼容性peer：next >=14.0.0；react >=18.0.0；typescript >=5.0.0
类型包内自带类型声明
  • Turbopack 方案在一个路由处理器里用 esbuild 编译 Service Worker，并用 git rev-parse 取版本号；standalone 制品里要额外带上 esbuild 二进制
  • 依赖里包含 @swc/core

适合我们吗：做离线草稿时再评估。

决定

所有者：不引入库：原生 manifest + 手写 Service Worker

封装层入口：src/app/manifest.ts、public/sw.js、src/app/offline/page.tsx

  • Service Worker 不缓存 /api/*，只缓存静态资源和离线页
  • sw.js 修改后版本号必须变化

放弃了什么：

  • Serwist：MVP 用不到；Turbopack 方案和 standalone 制品有耦合

已知代价：缓存策略手写。

何时重审：

  • 做离线草稿（v0.2）时
