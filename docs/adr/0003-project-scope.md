# ADR-0003：项目范围（对齐纪要）

- 状态：Accepted <!-- 被推翻时改为 Superseded by ADR-XXXX，正文不改 -->
- 日期：2026-10-31（负责人 2026-10-31 确认）
- 决策人：项目负责人（AI 整理）
- 来源：demo-init Phase 1 对齐纪要。按 skill 约定项目范围应为 0001，但 0001、0002 在新版流程之前已产生并被已合并的 PR 引用，编号保持不变（见 [README](./README.md)）。

## 背景

项目从 0 到 1 的需求散在多轮对话、[架构基线](../designs/architecture-baseline.md)、ADR-0001、ADR-0002 里，没有一份成文的范围定义。MVP 也没有做过减法。没有"暂不做"清单时，AI 很容易过度设计，所以按 demo-init Phase 1 补一份纪要。

## 面临的选项

- A. 一次做完负责人描述的全部功能
- B. 先做 5 项核心功能，其余明确列入"暂不做"

## 决定

采用 B。对齐纪要如下：

```
- 产品：DayDayOn，和朋友互相督促的多人打卡 PWA（运动 / 饮食 / 睡眠 / 学习 / 自定义），
        AI 帮忙看图记录；治愈可爱风，手机和电脑都好用
- 核心用户：负责人和朋友（华科同学为主）；所有注册用户进总榜，可选择不公开
- MVP（v0.1）：
  1. 邮箱验证码登录 + 新人引导（昵称、头像、基础资料、是否上榜）
  2. 设定目标（时间 + 内容）+ 五个板块手动打卡 + 每日满意度和体重
  3. 饮食拍照 AI 识别，连同它的前置：每周额度与兑换码、IP 风控、最简后台
  4. 主页仪表盘（固定布局）+ 排行榜
  5. 待办（清单 + DDL）
- 暂不做（v0.2 以后）：运动和睡眠截图解析、运动软件记录导入、自定义目标的 AI 提示词解析、
        热量缺口分析、联网搜索、时间日志模式、自定义仪表盘拖拽、离线草稿、Web 推送、
        深色模式、好友互动、APK 壳、Kotlin 原生
- 当前阶段：正式开发前，先在 /dev/playbook 做完基础组件库和各板块的专用组件，
        再搭建业务（登录、数据库、接口）
- 寿命 / 协作：正式项目，长期试点，以后可能并入 RootSolo；多个 Agent 交替开发
        → 完整启用自进化机制（ADR、lessons、组件库注册表、skills 注册表）
- 技术栈：Next.js 16.4（standalone）+ PostgreSQL 18（Docker 自托管）+ 阿里云 ECS（PM2 + 宝塔 Nginx）；
        AI 用 AI SDK + deepseek-flash
        规则包：nextjs（已按自托管改写）；edgeone、supabase 不加载
- 环境：Windows + PowerShell，pnpm 11.7，Node 24
- 红线：线上给真实用户用。安全敏感路径：登录与会话、AI 额度与兑换码（涉及钱）、后台、
        健康数据（体重、饮食、睡眠）、用户图片（不落盘）。这些路径禁止手写协议实现，只用成熟库
- 已有约定：main / dev 双分支、提交描述用中文、1037Solo 同款部署、端口 23329 / 23432
- 待决：组件库与各关注点的所有者（Phase 3，进度见 docs/plans/plan-demo-init-alignment.md）
```

## 理由

- 5 项核心功能已经能跑通"登录 → 定目标 → 打卡 → 看到进度 → 和朋友比"的闭环。
- 饮食拍照是唯一放进 MVP 的 AI 功能：它最能体现产品特点，而且会把额度、风控、后台这些"花钱前必须有"的基础设施一次带出来。
- 运动、睡眠截图解析复用同一套 AI 管线，放到 v0.2 只是多几个 prompt 和表单。

## 放弃了什么

- v0.1 没有运动和睡眠的 AI 解析，这两个板块先只能手动打卡。
- 仪表盘是固定布局，不能拖拽自定义。
- 没有可靠的打卡提醒（Web 推送在国内基本不可用，留到 APK 阶段）。

## 何时重审

- v0.1 上线、朋友试用两周后。
- 负责人新增必须进 MVP 的功能时。
- 决定并入 RootSolo 生态时（同时重审 ADR-0001）。
