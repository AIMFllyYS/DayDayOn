# ADR-0019：PWA 与 Service Worker——不引入库：原生 manifest + 手写 Service Worker

- 状态：Accepted（负责人 2026-10-31 拍板：Phase 3 的 17 项建议全部采纳）
- 日期：2026-10-31
- 决策人：项目负责人（AI 提供分析）
- 对比页：[docs/designs/library-showcase/16-pwa.html](../designs/library-showcase/16-pwa.html)

## 背景

- 可以安装到桌面（manifest、图标）
- 离线时显示兜底页
- 离线草稿放到 v0.2（ADR-0003）

先定的层：MVP 只要可安装 + 离线兜底，原生能力足够。

## 面临的选项

- **app/manifest.ts + 手写 public/sw.js**：推荐。和 standalone 部署没有耦合。
- **Serwist（Turbopack 方案）**（`@serwist/turbopack`）：备选。做离线草稿时再评估。

## 决定

不引入库：原生 manifest + 手写 Service Worker。

- 封装层入口：src/app/manifest.ts、public/sw.js、src/app/offline/page.tsx
- Service Worker 不缓存 /api/*，只缓存静态资源和离线页
- sw.js 修改后版本号必须变化

## 理由

和 standalone 部署没有耦合。

- Next 官方 PWA 指南即采用 manifest.ts + 手写 Service Worker
- 导航请求网络优先，失败时返回预缓存的离线页

## 放弃了什么

- Serwist：MVP 用不到；Turbopack 方案和 standalone 制品有耦合

已知代价：缓存策略手写。

## 何时重审

- 做离线草稿（v0.2）时
