## 1. 已确认的决策（2026-10-31）

| 项 | 决策 |
|---|---|
| 账号体系 | 独立：Better Auth + 本机 PostgreSQL，短期不迁入 1037Solo 生态 |
| 登录方式 | 邮箱 + 验证码，邮件走阿里云邮件推送 |
| 邮箱限制 | 只支持常见邮箱服务商，不支持自定义域名邮箱 |
| 图片 | 所有图片先由 DeepSeek 读图解析，**只把解析出的文本存进数据库，图片永不上云、永不落盘** |
| 模型 | **只用 `deepseek-flash`**，不使用 Pro |
| AI 预算 | 每人每周 10 元；兑换码一次加 10 元 |
| 风控 | 防批量注册，按 IP 做基础限流 |
| 后台 | 先做最简后台：额度监控、异常发现、封号 |
| 部署 | 沿用 1037Solo 同款部署方式，但目录放在 `/www/wwwroot/daydayon`，不使用 `/1037Solo` 下的任何路径 |
| 云服务 | 不使用腾讯云 |

## 2. 邮件推送（阿里云 DirectMail，SMTP）

应用需要 4 个配置项（来源：[SMTP 服务地址](https://help.aliyun.com/zh/direct-mail/smtp-endpoints)）：

| 环境变量 | 值 | 说明 |
|---|---|---|
| `SMTP_HOST` | `smtpdm.aliyun.com` | 华东 1（杭州）。控制台选了其他区域就用对应地址 |
| `SMTP_PORT` | `465` | SSL 加密。ECS 默认封禁 25 端口 |
| `SMTP_USER` | 发信地址，如 `noreply@mail.example.com` | 控制台"发信地址"里创建；SMTP 用户名必须与发信地址完全一致 |
| `SMTP_PASS` | SMTP 密码 | 在控制台为该发信地址单独设置，不是阿里云账号密码，也不是 AccessKey |

发信前在控制台完成：

1. 添加**发信域名**，按提示在 DNS 加记录：所有权验证、SPF、MX、DKIM（建议再加 DMARC）。不配 SPF / DKIM 时，Gmail、Outlook 很可能把验证码邮件判为垃圾邮件。
2. 在该域名下创建**发信地址**（类型选"触发邮件"），设置 SMTP 密码。

密码只写进服务器 `.env` 和本机 `.env.local`，不发到聊天里。

## 3. 邮箱白名单

注册与登录只接受以下域名（已确认）：

| 服务商 | 域名 |
|---|---|
| QQ | `qq.com`、`foxmail.com`、`vip.qq.com` |
| 网易 | `163.com`、`126.com`、`yeah.net` |
| Google | `gmail.com` |
| 微软 | `outlook.com`、`hotmail.com` |
| Apple | `icloud.com` |
| 华中科技大学 | `hust.edu.cn` |

白名单放在配置里，新增域名不需要改业务代码。

防止"一个邮箱注册多个号"：

- 邮箱统一转小写后存储和比较。
- 拒绝本地部分带 `+` 的地址（如 `a+1@gmail.com`）。
- Gmail 忽略本地部分的 `.`（`a.b@gmail.com` 与 `ab@gmail.com` 视为同一个邮箱）。

## 4. 图片处理流程

```
拍照 / 选图
  → 浏览器压缩（长边 ≤ 1600px，WebP）
  → POST /api/v1/...（multipart，限制大小）
  → 服务端只在内存中处理：校验格式 → 发给 deepseek-flash
  → 返回结构化草稿 + 解析文本
  → 用户确认或修改
  → 入库：结构化字段 + 解析文本（不含图片）
```

规则：

- 图片不写磁盘、不进数据库、不进日志（包括 base64）、不发给 DeepSeek 以外的任何服务。
- 请求结束后图片数据随内存释放；不做服务端缓存。
- 解析失败或置信度低时，降级为手动填写。
- 历史记录里看不到原图；识别有误只能手动改数值，不能事后重新解析。

## 5. AI 额度

### 5.1 计价依据（[DeepSeek 模型与价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)，2026-10-31）

`deepseek-flash` 每百万 tokens：

| | 高峰 | 空闲 |
|---|---|---|
| 输入（缓存命中） | 0.04 元 | 0.02 元 |
| 输入（缓存未命中） | 2 元 | 1 元 |
| 输出 | 8 元 | 4 元 |

- 高峰时段：北京时间周一至周五 9:00–12:00、14:00–18:00（不含法定节假日），其余为空闲。
- 联网搜索 Search / Fetch：每 1000 次成功请求 5 元，即 0.005 元 / 次。
- **扣费一律按高峰价计算**（已确认）：不区分时段，实现简单，也不会低估成本。DeepSeek 调价时只改配置里的价格表。

粗略估算：一次拍照识别约 1.5k 输入 + 0.5k 输出 tokens，按高峰价约 0.007 元；开思考模式输出变长，约 0.02 元。每周 10 元大约够 500–1400 次调用，正常使用很难用完，主要风险来自批量注册和盗刷。

### 5.2 账本设计

- 金额单位：**微元**（1 元 = 1,000,000 微元），整数存储。与 1037Solo 生态的 microcredits 单位相同，以后要并入时可以直接对应。
- 余额由三部分组成：
  - **本周额度**：每周一 00:00（北京时间）重置为 10 元，**没用完的部分清零，不累积**；
  - **加购余额**：兑换码充入，**长期有效，直到用完**；
  - **已预占未结算金额**。
- 扣费顺序：先扣本周额度，用完再扣加购余额。
- **新账号**：注册后本周额度先给 2 元；完成新人引导后，把当周额度补到 10 元（已用掉的照常计入）；从下一周起按正常的 10 元发放。
- 每次调用：
  1. 按"预估输入 tokens × 未命中输入价 + 最大输出 tokens × 输出价"**预占**；余额不足直接拒绝。
  2. 调用结束按 DeepSeek 返回的实际用量**结算**，多退少补（预占上限保证不会超扣）。
  3. 调用失败**释放**预占；已产生 token 的部分按实际用量结算。
  4. 每次操作带幂等键，重试不会重复扣费。
- 每次调用写一条 `ai_runs` 记录：用户、IP、用途、输入 / 输出 / 缓存命中 tokens、金额、耗时、状态。

### 5.3 兑换码

- 管理员在后台批量生成，每个码一次性使用，面值 10 元。
- 数据库只存兑换码的哈希。
- 兑换接口按用户和 IP 限流，防止暴力猜码。

### 5.4 全局保护

- 全站每日花费上限：**默认 10 元，管理员可在后台修改**。达到后当天自动暂停所有 AI 功能，并给管理员发邮件；次日 00:00（北京时间）自动恢复，或由管理员手动恢复。
- DeepSeek 账户只充值有限金额，作为最后一道硬上限。

## 6. 基础风控

应用只监听 `127.0.0.1`，所有请求都经过宝塔 Nginx，所以只信任 Nginx 写入的 `X-Real-IP` / `X-Forwarded-For`。

| 场景 | 限制（初始值，可调） |
|---|---|
| 发送验证码 | 同一邮箱 60 秒 1 次、每天 10 次；同一 IP 每小时 5 次、每天 20 次 |
| 新注册 | 同一 IP 每天最多 3 个账号 |
| 验证码校验 | 同一邮箱连续错 5 次，该验证码作废 |
| AI 调用 | 同一用户每小时 60 次，同时最多 2 个进行中 |
| 兑换码 | 同一用户每小时 5 次失败后锁定 1 小时 |

另外记录注册 IP、最近登录 IP，供后台按 IP 聚合查看。出现批量注册时再考虑接入阿里云验证码（按次计费，先不接）。

## 7. 后台管理（最简版）

- 入口 `/admin`，桌面端使用。
- 管理员身份：数据库里的 `role = admin`。管理员账号必须开启两步验证（Better Auth 的 TOTP）。
- 功能：
  - 用户列表：本周花费、调用次数、注册 IP、同 IP 账号数、状态
  - 异常标记：单人单日花费超过 5 元、每小时调用超过 60 次、同 IP 超过 3 个账号、兑换码失败过多
  - 操作：封号（附原因，可设到期时间）、解封、手动调整额度、生成兑换码、一键暂停全站 AI
  - 配置：全站每日花费上限（默认 10 元）、每周额度、新账号首周额度、各项限流阈值
  - 全站每日花费曲线
- 封号即时生效：被封用户的会话全部作废，AI 调用直接拒绝。
- 异常达到阈值时给管理员发邮件。

Better Auth 的 admin 插件提供角色、封禁、会话吊销；two-factor 插件提供 TOTP。

## 8. 排行榜可见性

- 选择不公开的用户**不出现在榜单上**（不以匿名占位）。
- 新用户默认不公开；新人引导里单独一步询问"是否加入排行榜"，之后可在"我的"里随时修改。
- 公开的只是聚合数据（打卡天数、连续天数等）；体重等精确指标即使公开排行也不展示具体数值。
