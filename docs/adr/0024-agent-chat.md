# ADR-0024 — Agent 对话：悬浮团团、工具调用与联网搜索

- 状态：Proposed
- 日期：2026-11-02
- 决策人：项目负责人（AI 整理，待拍板）

## 背景

项目已有完整的 AI 管线（`runAi` 预占/结算、`ai_runs`、额度账本、饮食拍照识别）和一套 Agent 前端组件（`AgentTurn`、`AiDraftCard` 等，只在 Playbook 用假数据回放）。但前端从未真实接入对话：没有流式接口、没有会话/消息存储、没有工具。

负责人要做一个「悬浮团团」：应用内常驻的 IP 小宠物，点击弹出 Agent 对话窗，全屏进独立页。Agent 能读用户数据、把自然语言整理成打卡/待办/体重草稿（确认后入库），并支持联网搜索、图片/文本附件。

ADR-0003 把「联网搜索」列为 v0.2 暂不做。本 ADR 推翻这一条：负责人明确要求饮食热量、运动 MET 等数值必须联网搜索后给出，而不是凭模型记忆编造。

## 面临的选项

- **接入方式**：在现有 `runAi` 之外另写一条流式 agent 路径（ToolLoopAgent），复用同一套账本预占/结算。
- **草稿 vs 直接写库**：AGENTS.md 硬规则「AI 结果先草稿、用户确认后入库」。可选：草稿 + 一键确认；直接写库 + 撤销；按把握度分流。
- **联网搜索**：DeepSeek 官方 Search / Fetch API（按次计费）vs 作为普通工具让模型自己决定。
- **思考模式**：默认关、输入框可切换 vs 一直开。

## 决定

1. **接入 ToolLoopAgent**：新增 `src/server/ai/agent.ts`（模型 + 指令 + 工具 + `stopWhen: isStepCount(12)`）与 `src/server/ai/run-agent.ts`（复用 `runAi` 的预占/结算账本）。流式接口 `POST /api/v1/agent/chat` 走 UI message stream，不走幂等中间件（流式响应体无法缓存），幂等由额度层的 `rejectReusedKey` 保证。
2. **草稿 + 一键确认**：写工具只返回结构化草稿（`draftCheckin` / `draftTodo` / `draftWeight`），前端渲染成 `AiDraftCard`，用户确认后调普通创建接口。硬规则不变。
3. **联网搜索**：DeepSeek 官方 `POST /v1/tools/search`、`POST /v1/tools/fetch`，由模型自己决定何时搜；饮食热量、运动 MET 等数值在提示词里写明「必须先搜」。每次成功约 5000 微元计入额度。每轮最多 10 次。
4. **思考模式**：默认 `thinking: disabled`；输入框「深度思考」开关打开时用 `reasoningEffort: 'low'`（DeepSeek 最低档）。
5. **会话与消息**：新增 `agent_conversations` + `agent_messages`（parts jsonb）。用户图片永不落盘：入库前把 file part 换成文字说明。`AiPurpose` 增加 `agent-chat`。
6. **悬浮团团**：应用内全局显示（我的页、全屏页、登录/引导、后台隐藏）。手势：点开弹窗、拖动、长按晃悠、双击转圈；边缘 ≤24px 吸附露半头，顶部倒立，底部受 Dock 栏阻挡。弹窗从团团角落弹出，手机顶部留 1/3、左侧留 1/4。

## 理由

- 复用现有账本（预占上限 = 12 步 × 单步输出 + 10 次联网）保证多步循环不会超扣。
- 草稿 + 确认维持「用户是最终决定者」的产品原则，也避免 AI 直接写库带来的误记风险。
- DeepSeek 官方搜索按次计费、结果结构化（`summary` 给模型读），比自建搜索更省事且可审计。
- 思考默认关：开启费用约为关闭的 2–3 倍，且只有推理链有内容可展示时才值得开。

## 放弃了什么

- 直接写库 + 撤销（违背现有硬规则，且撤销窗口语义复杂）。
- 自建搜索 / 网页抓取（重复造轮子，且不如官方 API 稳定）。
- 让 `deepseek-flash` 之外引入 vision 专用模型 id（现有管线已统一 `deepseek-flash`）。

## 何时重审

- 联网搜索按次计费上线后，核对真实花费与 5000 微元/次的估算是否一致。
- 悬浮团团的手势若被证明误触率高，重审「点击 vs 拖动 vs 长按」的判定阈值。
