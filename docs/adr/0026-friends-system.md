# ADR-0026：好友体系（6 位配对码、双向透明小窝舞台、轻互动与可控 1v1 私聊）

- **状态**：Accepted（2026-11-02 初版落地；2026-11-16 修订：上线可控 1v1 私聊与小窝互动；2026-11-23 修订：好友公开范围扩展至「各板块近况（近 7 天）」与只读「目标详情」）
- **日期**：2026-11-02（修订日期：2026-11-23）
- **决策人**：项目负责人

## 背景

DayDayOn 定位为「和朋友一起用的治愈系多人打卡应用」。此前排行榜（`/rank`）仅展示全站开启上榜用户的模糊打卡天数，缺乏熟人好友之间点对点、完全透明的互相监督体验。因此需要引入轻量、高仪式感的好友体系，并与顶栏导航、主页打卡仪表盘以及团团 Agent 工具链深度打通。

## 面临的选项

1. **配对方式**：
   - 选项 A：搜索昵称/邮箱 + 发送好友申请列表 + 消息中心审批流
   - 选项 B：6 位数字配对码（10 分钟有效，点击「发起邀请」开始计时，中途关闭弹窗再打开仍保持原配对码与真实剩余时间）+ 接受方输入配对码后居中弹窗二次确认
2. **隐私边界**：
   - 选项 A：提供模块级或字段级的好友可见性开关
   - 选项 B：第一性原理——添加好友的核心目的就是双方互相公开监督，结为好友后双方完整的打卡仪表盘（今日进度、热力图、体重趋势、心情）彻底公开且不可单向关闭（在发起和接受邀请时明确告知）
3. **好友仪表盘展示架构**：
   - 选项 A：新建独立动态路由 `/friends/[friendId]`
   - 选项 B：主页 `/` 原位视角切换 + 只读 `HomeDashboard`（通过顶栏左上角 `AvatarStack` 悬浮面板一键切换「我自己 ↔ 好友」）

## 决定

1. **采用 6 位 10 分钟持久化配对码 + 好友上限 50 人（选项 B）**：
   - 点击右上角 `+` → `添加好友`（或头像面板底部快捷添加按钮）弹出底部 `Sheet`，提供「发起邀请」与「接受邀请」两个入口。
   - 点击「发起邀请」时由后端 `friend_invites` 表生成或复用当前未过期的 6 位配对码（有效期 10 分钟）。用户点空白处关闭抽屉再重新进入时，仍返回同一配对码与真实剩余倒计时，满 10 分钟或被使用后自动失效清空。
   - 点击「接受邀请」在底部 `Sheet` 内复用 `OTPField` 输入 6 位配对码，校验通过后弹出**屏幕正中央二次确认弹窗**（展示邀请方大头像与昵称，左下「取消」、右下「接受」）。
   - **好友数量上限 `50` 人**（`MAX_FRIENDS = 50`）：接受邀请时若双方任一方已达 50 位好友，事务内拦截并返回 409 `FRIEND_LIMIT_REACHED`。
   - 点击「接受」后触发仪式感动效：屏幕中央化作流星飞向左上角顶栏头像 → 左上角头像 Q 弹展开为 `AvatarStack` 叠放头像 → 浮现引导气泡「点击这里可以看到好友的打卡情况～」。
2. **双方打卡仪表盘与目标近况完全透明公开且不可关闭（选项 B）**：
   - 不设单向隐私开关，省去冗余状态与配置的心智负担；在发起邀请与接受邀请确认弹窗中均明确提示双方将公开完整打卡信息（含今日进度、各板块近况、目标记录、热力图、体重与心情）。
   - **2026-11-23 扩展**：好友空间（`/` 原位只读 `HomeDashboard`）同步展示该好友的「各板块近况 · 近 7 天」（`/api/v1/friends/{friendUserId}/insights`），点击任一板块卡片或今日进度项可进入二级只读路由 `/friends/[friendUserId]/goals/[goalId]` 查看该好友的目标设定、打卡日历与打卡历史（顶栏全端居中显示「`<好友昵称>的目标详情`」）。只读接口严格执行「双向好友关系 + `friendUserId` 资源归属」双重校验，严禁暴露编辑/删除/打卡写操作、留痕历史（`revisions`）与内部 AI 运行 ID / 原始解析文本。
3. **主页 `/` 原位视角切换、顶栏 `AvatarStack` 与好友管理二级菜单**：
   - 顶栏左上角复用 `AvatarStack`（`max = 4`，最多展示 4 个叠加头像 + `+N`），点击弹出好友面板（第一行置顶本人，下方按添加时间正序排列好友）。
   - 单击任意行在 `/` 原位切换本人或只读 `HomeDashboard`；**长按（420ms）或右键**好友行在面板内展开二级管理菜单（「进入好友空间」/「删除此好友」）。处于好友空间时，顶栏右上角 `+` 菜单第一项同步切换为红色的「解除此好友」。
4. **串门小窝动态舞台、宠物轻互动与 24h 静默造访足迹（`FriendRoomBanner` + `pet-interactions`）**：
   - 串门进入好友空间时，顶部展示动态宠物小窝舞台（`InteractivePet` 根据好友今日目标完成状态切换睡眠/欢呼/开心神态，全勤时盖「全勤」印章），此时右下角全局悬浮 AI 宠物自动隐藏（一屏不放两只互动宠物）。
   - 提供三项轻互动按钮（受同一类型 **30 分钟 / 1800 秒冷却**与**按被互动好友本地时区及 `dayStartHour` 计算的每日限额**约束，并写入 `friend_pet_interactions` 表与 `pet_interaction` 通知）：
     - **戳戳（`poke`）**：每日上限 `3` 次；
     - **投喂零食（`feed`）**：每日上限 `1` 次，点击展开 **6 格零食架**（海苔饭团 `onigiri`、奶油草莓 `strawberry`、黄油曲奇 `cookie`、焦糖布丁 `pudding`、三色团子 `dango`、晚安热奶 `milk`），支持拖拽或点选投喂触发专属宠物反应；
     - **提醒打卡（`remind`）**：每日上限 `1` 次，仅好友今日有计划且尚未全勤时可用（否则置灰显示「今日休息」或「今日已达标」）。
   - **24 小时静默造访足迹**：打开好友仪表盘（`getFriendDashboard`）时调用 `recordVisitFootprint`，在 24 小时内多次造访同一好友仅合并更新 `visitCount` 与最近访问时间，不重复弹窗骚扰。
5. **可控 1v1 好友私聊（修订原"放弃站内聊天"决定，`src/server/services/chat/`）**：
   - **修订说明**：2026-11-02 初版曾决定放弃站内好友聊天；为完善熟人打卡搭子的日常沟通与鼓励闭环，现正式修订该决定并上线**可控的纯文本 1v1 好友私聊**（`chat_messages` 表，单条 ≤ 300 字，路由 `/chats` 与 `/chats/{friendUserId}`）。
   - **敏感词过滤与持久化防刷冷静期**（`src/server/moderation/`）：发送私信必经本地 DFA Trie 敏感词过滤，命中返回 422 `CONTENT_SENSITIVE`（保留用户 `draft` 草稿，审计日志 `moderation_violations` 仅存文本 SHA-256 哈希）；基于 PostgreSQL `rate_limit_counters` 持久化频控，10 秒内发送超过 5 条或 24 小时内违规 ≥ 5 次即触发 **24 小时静音冷静期**（返回 403 `USER_MUTED` + `retryAfterSeconds`）。
   - **解除好友后历史只读归档**：双方解除好友关系后禁止发送新消息（返回 403 `FRIEND_RELATION_FROZEN`），但曾有私聊往来的前好友会话仍保留并标记 `isFrozen: true` 供双方只读查阅。
6. **团团 Agent 工具穿透**：
   - 新增 `listFriends` 与 `getFriendStatus` 两个 Agent 只读工具，支持团团直接读取好友列表及指定好友的今日仪表盘与近期打卡记录，用于对比鼓励。

## 放弃了什么

- 放弃了单向隐私屏蔽开关（保持熟人打卡搭子完全透明监督体验），以及无内容风控的自由群聊/多媒体富文本发送（站内聊天严格收敛为受本地 DFA 审核与防刷冷静期保护的纯文本 1v1 私聊）。
- （历史修订记录：2026-11-02 初版曾放弃站内聊天，已于上述第 5 条正式修订为可控 1v1 私聊。）

## 何时重审

- 未来若引入多人打卡小组（Group/Room）或需要调整好友上限（当前 50 人）、私聊频率或轻互动冷却时长时，在现有表结构上扩展重审。
