# ADR-0026：好友体系（6 位 10 分钟持久化配对码、双向完全透明仪表盘与 Agent 工具穿透）

- **状态**：Accepted
- **日期**：2026-11-02
- **决策人**：项目负责人

## 背景

DayDayOn 定位为「和朋友一起用的治愈系多人打卡应用」。此前排行榜（`/rank`）仅展示全站开启上榜用户的模糊打卡天数，缺乏熟人好友之间点对点、完全透明的互相监督体验。因此需要引入轻量、高仪式感的好友体系，并与顶栏导航、主页打卡仪表盘以及团团 Agent 工具链深度打通。

## 面临的选项

1. **配对方式**：
   - 选项 A：搜索昵称/邮箱 + 发送好友申请列表 + 消息中心审批流
   - 选项 B：6 位数字配对码（10 分钟有效，点击「发起邀请」开始计时，中途关闭弹窗再打开仍保持原配对码与真实剩余时间）+ 接受方输入配对码后居中弹窗二次确认
2. **隐私边界**：
   - 选项 A：提供模块级或字段级的好友可见性开关
   - 选项 B：第一性原理——添加好友的核心目的就是双方互相公开监督，结为好友后双方完整的打卡仪表盘（今日进度、热力图、体重趋势、心情）彻底公开且不可单向关闭（在发起和接受邀请时明确告知）
3. **好友仪表盘展示架构**：
   - 选项 A：新建独立动态路由 `/friends/[friendId]`
   - 选项 B：主页 `/` 原位视角切换 + 只读 `HomeDashboard`（通过顶栏左上角 `AvatarStack` 悬浮面板一键切换「我自己 ↔ 好友」）

## 决定

1. **采用 6 位 10 分钟持久化配对码（选项 B）**：
   - 点击右上角 `+` → `添加好友` 弹出底部 `Sheet`，提供「发起邀请」与「接受邀请」两个入口。
   - 点击「发起邀请」时由后端 `friend_invites` 表生成或复用当前未过期的 6 位配对码（有效期 10 分钟）。用户点空白处关闭抽屉再重新进入时，仍返回同一配对码与真实剩余倒计时，满 10 分钟或被使用后自动失效清空。
   - 点击「接受邀请」在底部 `Sheet` 内复用 `OTPField` 输入 6 位配对码，校验通过后弹出**屏幕正中央二次确认弹窗**（展示邀请方大头像与昵称，左下「取消」、右下「接受」）。
   - 点击「接受」后触发仪式感动效：屏幕中央化作流星飞向左上角顶栏头像 → 左上角头像 Q 弹展开为 `AvatarStack` 叠放头像 → 浮现引导气泡「点击这里可以看到好友的打卡情况～」。
2. **双方打卡仪表盘完全透明公开且不可关闭（选项 B）**：
   - 不设单向隐私开关，省去冗余状态与配置的心智负担；在发起邀请与接受邀请确认弹窗中均明确提示双方将公开完整打卡信息。
3. **主页 `/` 原位视角切换 + 只读 `HomeDashboard`（选项 B）**：
   - 顶栏左上角复用 `AvatarStack`（最多展示 3 个头像 + `+N`），点击弹出好友面板（第一行置顶本人，下方按顺序排列好友）。
   - 选中好友后在 `/` 原位渲染只读 `HomeDashboard`（禁用打卡跳转与指标编辑，顶部展示视角横幅与「返回我的主页」按钮）。
4. **团团 Agent 工具穿透**：
   - 新增 `listFriends` 与 `getFriendStatus` 两个 Agent 只读工具，支持团团直接读取好友列表及指定好友的今日仪表盘与近期打卡记录，用于对比鼓励。

## 放弃了什么

- 放弃了站内好友聊天与单向隐私屏蔽开关，保持熟人打卡搭子纯粹、零负担的透明监督体验。

## 何时重审

- 未来若引入多人打卡小组（Group/Room）或好友互动拍一拍功能时，在此表结构基础上扩展。
